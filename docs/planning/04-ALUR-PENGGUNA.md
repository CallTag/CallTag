# 04. Alur pengguna end-to-end

Status: **PROPOSED**. Alur as-is yang sudah terdokumentasi ada di [FLOWS_AND_DIAGRAMS](../FLOWS_AND_DIAGRAMS.md) dan tidak diulang; dokumen ini mendefinisikan alur **target**. Endpoint bertanda `(+)` adalah tambahan baru ([07](07-KONTRAK-API.md)). Kode acceptance `AC-xx` dipakai di [15](15-RENCANA-PENGUJIAN.md).

| # | Alur | Aktor | Tujuan | Prasyarat | Langkah utama | Alternatif / kesalahan | Endpoint | Operasi DB | Keamanan | Acceptance |
|---|---|---|---|---|---|---|---|---|---|---|
| 1 | Instalasi dan onboarding | Pengguna baru | Siap dilindungi dengan izin minimum | APK terpasang, Android ≥ 8 | Jelaskan tujuan dan privasi → buat `install_id` → daftar perangkat → minta role Call Screening → izin notifikasi → overlay opsional | Izin ditolak: aplikasi tetap bisa lookup manual; offline: seed direktori aktif, daftar ditunda | `POST /auth/device` | Room seed; `users`, `devices` upsert | Tanpa kumpulkan nomor/kontak; consent tercatat lokal | AC-01: tanpa izin, lookup manual dan direktori tetap berfungsi |
| 2 | Registrasi dan login | Pengguna | Principal server | Jaringan | Panggil auth → simpan token terenkripsi (EncryptedSharedPreferences/Keystore) → refresh otomatis | `401` refresh gagal → daftar ulang; offline → mode guest lokal | `POST /auth/device`, `POST /auth/refresh (+)` | `users`, `devices`, `refresh_tokens` | Token tidak di log; hash refresh di server | AC-02: token tidak valid menghasilkan 401, bukan guest |
| 3 | Pencarian nomor | Pengguna/Guest | Reputasi jujur | Input nomor | Validasi → E.164 → cache Room (cek TTL) → API → tampilkan status tampilan | Cache kedaluwarsa + offline: tampil "data lama, belum diverifikasi"; gagal: ERROR/OFFLINE, bukan CLEAN | `GET /phones/{e164}` | baca `phone_tags`, Room upsert | Kuota guest; tanpa nomor utuh di log | AC-03: nomor tak dikenal tidak pernah "aman" |
| 4 | Lihat tag komunitas | Pengguna | Memahami alasan skor | Hasil lookup | Buka rincian → laporan teredaksi + tag teragregasi | Tidak ada laporan: empty state | `GET /phones/{e164}/reports` | baca `spam_reports` (proyeksi aman) | DTO publik tanpa reporter id/PII | AC-04: respons tanpa `reporter_user_id` |
| 5 | Panggilan masuk dan Caller ID | Android Telecom | Peringatan cepat | Role screening dipegang | `onScreenCall` → normalisasi → cache → (API 800 ms bila cache miss) → alert | Batas total < 5 s, selalu `allow` pada `finally`; hasil UNKNOWN: tanpa alert menyesatkan | `GET /phones/{e164}` | Room baca/tulis log (tanpa nomor utuh di analitik) | Fail-open | AC-05: callback selesai < 5 s pada uji timeout |
| 6 | Pemblokiran otomatis | Sistem | Blokir hanya yang pasti | Toggle opt-in ON | Level DANGER_SCAM + data server ≤ 14 hari + bukan whitelist/kontak → reject + notifikasi dapat dibatalkan | Seed/stale/UNKNOWN: izinkan; pengguna tandai "bukan spam" | - (lokal) | Room `screening_logs` | Konservatif; keputusan dicatat | AC-06: SPAM/SUSPICIOUS/seed tidak pernah diblokir |
| 7 | Kirim laporan | User | Berkontribusi | Login, kuota tersisa | Isi kategori/tag/komentar → validasi → `Idempotency-Key` → kirim → tampil "diterima server, menunggu moderasi" bila di-hold | `429` kuota; `400` validasi; jaringan gagal → alur 8 | `POST /reports` | `spam_reports` insert unik, `phone_tags` agregasi, `sync_changes` | Principal dari token; sanitasi PII; kuota | AC-07: duplikat kunci idempotensi tidak membuat dokumen ke-2 |
| 8 | Laporan saat offline | User | Tidak kehilangan niat melapor | Offline | Simpan ke `pending_reports` Room (status `PENDING`) → tampil "tersimpan di perangkat, belum terkirim" | Skor lokal **tidak** berubah | - | Room `pending_reports` | Data pending dienkripsi at-rest oleh OS; komentar dibatasi | AC-08: pending tidak mengubah skor/blokir |
| 9 | Sinkronisasi laporan tertunda | Sistem | Kirim ulang aman | Jaringan kembali | WorkManager unik + backoff → kirim dengan kunci sama → tandai `SENT`/`REJECTED` | `409` sama: tandai terkirim; `4xx` permanen: `FAILED` + pesan; restart app: pending tetap | `POST /reports` | Room status; Mongo idempoten | Retry terbatas; tidak ulang bila `401` tanpa refresh | AC-09: restart aplikasi mempertahankan pending dan mengirim sekali |
| 10 | Pengajuan sanggahan | Pemilik nomor/User | Koreksi false positive | Nomor ada di sistem | Isi alasan + kontak balik + bukti opsional → server simpan dulu → balas `dispute_id` + token pelacak | Offline: antre di outbox (status "belum terkirim", bukan UNDER_REVIEW); duplikat dispute aktif ditolak | `POST /disputes`, `GET /disputes/{id}` (+) | `moderation_cases` insert, `audit_logs` | Rate limit; kontak balik dibatasi; tidak ada PII publik | AC-10: 201 hanya setelah tulis sukses dan ID dapat dibaca ulang |
| 11 | Tinjauan oleh moderator | Moderator | Putuskan tepat dan terjejak | Login staf + TOTP | Antrean → buka kasus → lihat bukti → putuskan (terima/tolak/butuh info) + alasan → status berubah → `sync_changes` | Konflik dua staf: optimistic lock `version`; salah putus: balik dengan alasan | `GET/PATCH /admin/cases` (+) | `moderation_cases`, `phone_tags`, `audit_logs`, `sync_changes` | RBAC, CSRF, audit append-only | AC-11: tiap keputusan memiliki aktor, alasan, waktu |
| 12 | Verifikasi pemilik nomor (P2) | Pemilik | Hak koreksi | Fitur P2 aktif | Pilih metode → bukti kontrol nomor → status `VERIFIED_OWNER` pada dispute | OTP gagal/kuota habis | `/owner/*` (+, P2) | `owner_claims` | Kuota biaya OTP | Ditunda; AC dibuat saat P2 disetujui |
| 13 | Layanan darurat | Pengguna | Menghubungi layanan cepat | - | Tab Darurat → nomor nasional → `ACTION_DIAL`; lokal bila wilayah dipilih | Offline: seed/cache; data kedaluwarsa diberi tanggal verifikasi | `GET /emergency/*` | baca `emergency_directory` | Hanya nomor terkurasi; tidak ada klaim tersambung | AC-13: seluruh nomor nasional tersedia offline |
| 14 | Kelola direktori | Admin | Data resmi mutakhir | Login ADMIN | Tambah/ubah entri + sumber + tanggal verifikasi → simpan → `sync_changes` | Validasi nomor/duplikat | `POST/PUT /admin/emergency` (+) | `emergency_directory`, `audit_logs` | Hanya ADMIN | AC-14: entri tanpa sumber ditolak |
| 15 | Pencarian via website | Pengunjung | Cek nomor tanpa aplikasi | - | Input → API publik → hasil sama dengan Android (status jujur) | CORS/jaringan gagal: pesan error, bukan seed sebagai nyata | `GET /phones/{e164}` | baca saja | Guest kuota; tanpa form lapor pada MVP (alur 7 hanya di aplikasi) | AC-15: tidak ada data seed tanpa label "contoh" |
| 16 | Sinkronisasi Android ↔ backend | Sistem | Cache terbaru dan benar | Terdaftar atau guest | Kirim `cursor` opak → terima halaman perubahan UPSERT/DELETE → terapkan dalam satu transaksi Room → simpan cursor | `has_more` ulang sampai habis; `generation` berubah → full resync | `GET /sync/changes (+)` (menggantikan offline-bundle) | `sync_changes` baca; Room transaksi | Respons tanpa PII | AC-16: dua perubahan satu detik keduanya terkirim |

Konsistensi lintas klien: Android dan website memakai kontrak status yang sama (`availability` + `reputation_level`) sehingga nomor yang sama tampil sama.
