# Tahap 5B — Bukti implementasi dan pengujian

Tanggal: 16 November 2026, WIB. Repositori Android `CallTag`, perubahan lokal sebelumnya dipertahankan. Tidak ada commit/push/rilis.

## Implementasi T-308–T-314

- Mode Tamu eksplisit: pencarian/darurat/kanal resmi/sanggahan tetap terbuka. Laporan, riwayat pribadi, whitelist, dan `/me` memerlukan login. Token lama tidak mengaktifkan akun; interceptor tidak lagi mendaftarkan tamu otomatis.
- Login nama tampilan dan nomor opsional; logout menutup sesi, membersihkan state UI pribadi dan menjeda outbox. Kepemilikan laporan mengikuti ID pengguna server. Laporan lama tanpa pemilik dijeda dan tidak dapat dikirim ulang dengan sesi baru.
- Tab kelima Akun: profil/kuota, logout, konfirmasi hapus akun, tema persisten, bersihkan cache non-fixture, pintasan Proteksi, tutorial, diagnostik izin/backend yang diperbarui setelah kembali dari Settings.
- Whitelist lokal per akun: normalisasi nomor, tambah/hapus, pemeriksaan pada kebijakan screening; tidak diunggah ke server.
- Feedback: kategori, deskripsi, versi APK/model/Android; salin dan chooser berbagi. Token/nomor yang ditempel pada deskripsi disamarkan. Tidak ada alamat penerima rekaan atau pengiriman otomatis.
- Prefix seluler/PSTN/negara identik backend: 453 kasus bersama, salinan fixture Android memiliki SHA-256 identik. Normalisasi mempertahankan `+855`, `+81`, dan layanan `150xxxx`.
- Hasil pencarian menampilkan konteks UNKNOWN/OFFLINE, sumber/tanggal verifikasi resmi, chip tag dengan count, tambah tag, dan WhatsApp `ACTION_VIEW`. Form mendukung `INFO_TAG` netral; kategori gangguan dipisahkan.

## Hasil pengujian

```bash
# BUILD SUCCESSFUL; 14 tests, 0 failures, 0 errors, 0 skipped
cd ../backend
go test ./helper -run TestCarrierContextSharedAndroidFixture -v -count=1
# PASS; 453 kasus fixture
```

Empat kelas JVM: `CallTagTahap5UnitTest` (6), `PhoneContextTest` (4), `FeedbackDiagnosticsTest` (2), `SessionAccessPolicyTest` (2). Satu metode parity memeriksa seluruh 453 kasus. Kedua repositori lulus `git diff --check`. [Log build terakhir](2026-11-16-stage-5b-tests.txt).

Emulator `Pixel_5_Light`, Android 14/API 34, 1080×2340, density 440. APK debug dipasang dan dibuka. Backend uji berjalan lokal di port 8080 dengan penyimpanan memory terisolasi dari MongoDB kerja.

| BCA `08111500998` | Label resmi, source BCA, tanggal verifikasi, aksi WhatsApp tampil |
| Nomor `+855...` | Tetap internasional, konteks Kamboja, Belum Ada Data; preview menampilkan konteks yang sama |

## Batas bukti

- Pemeriksaan taste-skill disesuaikan ke UI Android: token native, kontras, hierarki, tepi konsisten, dan pemeriksaan screenshot. Tidak menggunakan aset HTML atau checker browser untuk Compose.
- Prefix merupakan konteks alokasi nomor, bukan pencarian HLR jaringan langsung. Tabel negara mencakup subset 54 kode yang sama dengan backend; WhatsApp dibatasi kode yang dikenal dan nomor lengkap valid. Nomor layanan nasional tidak diberi deep-link.
- Metadata verifikasi diperlihatkan pada hasil server langsung. Verifikasi tidak dipercaya dari cache tanpa bukti masa berlaku; tidak ada perubahan skema Room.
- Panggilan seluler nyata, variasi OEM, penerimaan pesan oleh aplikasi WhatsApp/Email tujuan, dan penghapusan akun sungguhan belum diuji. Suite JVM tidak menggantikan pengujian tersebut.
- Butir `[ANDA]` pada checklist tidak dicentang otomatis; tetap tersedia untuk peninjauan pengguna.
