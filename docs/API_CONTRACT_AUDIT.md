## Envelope, status, error, unknown, dan null

Backend menulis envelope sukses `success/code/message/data/timestamp`; timestamp dibuat UTC saat respons. Error memakai envelope yang sama tetapi `data` **tidak muncul** karena field interface nil + omitempty. Jangan menuliskan bahwa backend selalu mengirim `data:null`: [backend/model/model.go:32](https://github.com/CallTag/backend/blob/86763140b85def8578ca83969f5264ce667f16b2/model/model.go#L32), [backend/helper/response.go:40](https://github.com/CallTag/backend/blob/86763140b85def8578ca83969f5264ce667f16b2/helper/response.go#L40). Android menerima data nullable dan timestamp nullable ([CallTag/app/src/main/java/id/calltag/app/data/remote/dto/ApiDtos.kt:38](https://github.com/CallTag/CallTag/blob/42e9ceba72b89ba2728901559c6966bd80f683e0/app/src/main/java/id/calltag/app/data/remote/dto/ApiDtos.kt#L38)).

OpenAPI hanya mencantumkan status sukses per path, tidak memasang ErrorResponse pada respons 400/405/500/404. Router mengembalikan 404 untuk route tak dikenal, OPTIONS 204 untuk semua path; handler memberikan 405 untuk method salah kecuali health yang tidak memeriksa method. Health bukan probe DB aktif, hanya membaca MongoConnected hasil startup ([backend/route/route.go:24](https://github.com/CallTag/backend/blob/86763140b85def8578ca83969f5264ce667f16b2/route/route.go#L24), [backend/route/route.go:66](https://github.com/CallTag/backend/blob/86763140b85def8578ca83969f5264ce667f16b2/route/route.go#L66), [backend/controller/sync.go:83](https://github.com/CallTag/backend/blob/86763140b85def8578ca83969f5264ce667f16b2/controller/sync.go#L83)).

Riwayat nomor belum dikenal menghasilkan reports[] dan recent_reports[] ([backend/controller/lookup.go:52](https://github.com/CallTag/backend/blob/86763140b85def8578ca83969f5264ce667f16b2/controller/lookup.go#L52), [backend/controller/lookup.go:138](https://github.com/CallTag/backend/blob/86763140b85def8578ca83969f5264ce667f16b2/controller/lookup.go#L138), [backend/model/model.go:210](https://github.com/CallTag/backend/blob/86763140b85def8578ca83969f5264ce667f16b2/model/model.go#L210)). Kasus tambahan: report tanpa auth dan dengan JWT invalid tetap 201; report riwayat tanpa auth 200; phone/kategori invalid 400; short code report 400 (bukan 403); method salah 405 dan route hilang 404. ## Usulan kontrak kompatibel dan urutan remediasi

1. Dokumentasikan perilaku v1 yang ada lebih dahulu: schema envelope untuk 11 operasi, ErrorResponse terpasang di status nyata, parameter type/limit/bounds, unknown 200 found:false, nullable/omitted secara eksplisit. Pertahankan alias risk_score/spam_score, reports/recent_reports, custom_tag/tag_name selama migrasi. Tandai Bearer opsional saat v1 masih menerima guest; jangan tiba-tiba memaksa 401 yang memutus app/web.
2. Tambahkan identitas record stabil sebagai field baru misalnya report_record_id sambil mempertahankan report_id komposit sebagai legacy. Tambahkan client_request_id opsional dengan deduplikasi idempotency di penyimpanan; tangani retry setelah partial failure. Pisahkan duplicate dokumen dari unique scoring. Jangan mengubah makna report_id diam-diam.
3. Simpan dispute secara durable dan beri ID unik sebelum menyatakan diterima; bila belum tersedia, dokumentasikan sebagai demo acknowledgment, dan UI jangan menyebut antrean review. Tambahkan outbox Room report/dispute beserta status pending/sent/failed dan replay idempotent; hasil agregasi lokal tetap bisa tersedia dengan provenance lokal.
4. Tambahkan mekanisme sync aman secara additive: opaque next_cursor dengan urutan (sync_version,id), has_more, dan event/tombstone perubahan CLEAN. Pertahankan request since_version lama selama masa transisi. Simpan remote cursor terpisah dari sync_version cache/lokal, loop semua halaman. Versi harus monoton dan unik terhadap perubahan, bukan detik saja.
5. Normalisasi koleksi backend ke []/{} atau deklarasikan nullable dan sanitasi DTO sebelum penggunaan. Pertahankan data nullable pada error envelope. Uji explicit null, key omitted, unknown 200, daftar kosong, secondary query gagal, ID string/legacy, cursor terpotong, dan update satu detik sebagai kasus kontrak bermakna.
6. Petakan CALL/WHATSAPP/BOTH web ke kebijakan media yang disepakati, atau dokumentasikan alias legacy; validasi baru perlu masa kompatibilitas. Sesuaikan auth dengan model guest yang disengaja; autentikasi nomor memerlukan pembuktian kepemilikan sebelum disebut identitas terverifikasi.
7. Buat simulator berdasarkan fixtures envelope/status per endpoint, cabang error, query, dan schema yang sama. Tampilkan sumber simulasi per respons. Pertahankan 0 sebagai 0 pada statistik live dan sebut jumlah nomor berisiko sesuai maknanya; provenance seed/remote harus konsisten termasuk komentar dan hasil refresh setelah submit.

Usulan ini belum diimplementasikan. Perubahan hanya pada dokumen audit dan matriks; deployment, API, DTO, algoritme, dan data tidak diubah oleh dokumen ini.
